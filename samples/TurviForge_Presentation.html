The Problem

JMeter's built-in HTML dashboard hasn't evolved in a decade:

❌ Inaccurate Percentiles

10–30% error at p99/p99.9 from coarse bucket interpolation. SLAs live at p99+.

❌ No Comparison

No way to diff two runs without external tooling (Grafana, Excel, scripts).

❌ No Verdict

Descriptive, not evaluative. No pass/fail, no CI exit code. Teams bolt on Taurus.

❌ Poor Scalability

Struggles beyond a few GB. Multi-hour soak tests routinely fail to render.

Result: 1–3 hours per test cycle on manual post-processing.

The Solution

A drop-in JMeter plugin that fully replaces the stock dashboard:

  • Exact-grade percentiles — log-linear histogram, ≤0.78% error at p99.9
  • SLA gates — declarative YAML → PASS / DEGRADED / FAIL → exit codes + JUnit XML
  • Run-to-run comparison — Mann-Whitney U + Cliff's delta, regression detection
  • Single self-contained HTML — all JS/CSS/data inlined, works offline, email-able
  • Constant memory — streaming parse, handles 10 GB+ JTL in <512 MB heap
  • Zero friction — one JAR in lib/ext, no test plan changes required

Usage — CLI

# Generate report with SLA evaluation java -jar turviforge-cli.jar generate \ --jtl results.jtl --out report/ \ --sla sla.yaml --junit \ --title "Checkout API — RC 2.4" # Auto-generate SLA from a baseline run java -jar turviforge-cli.jar sla \ --jtl baseline.jtl --out sla.yaml --headroom 50 # Compare two runs java -jar turviforge-cli.jar compare \ --baseline base/report-data.json \ --candidate cand/report-data.json --out diff/ # Validate SLA syntax java -jar turviforge-cli.jar validate --sla sla.yaml

Exit codes: 0 PASS · 1 FAIL · 2 usage · 3 input · 4 internal

SLA Engine

Declarative YAML

version: 1 defaults: window: steady-state apdex: { satisfied_ms: 400, tolerated_ms: 1200 } rules: - match: "Checkout*" assert: - { metric: p95, op: "<", value: 800, warn: 700 } - { metric: error_rate, op: "<", value: 0.5 } - match: "TOTAL" assert: - { metric: throughput, op: ">=", value: 100 }

Three-Level Verdict

  • PASS — all assertions met
  • DEGRADED — warn thresholds breached
  • FAIL — hard thresholds breached

CI Integration

  • Non-zero exit code on FAIL
  • JUnit XML for pipeline UIs
  • Verdict banner in HTML report
  • Per-rule evaluation table

Comparison Engine (M5)

Statistically rigorous run-to-run comparison:

Statistical Tests

  • Mann-Whitney U — rank-sum significance from histogram data
  • Cliff's delta — effect size (|d| ≥ 0.147 = small effect)
  • Dual threshold: significant AND exceeds tolerance

Regression Detection

  • p95 regression > 10% with significance
  • Error rate increase > 0.2 pp
  • Throughput drop > 10%
  • Per-label delta table in report

No raw samples needed — works entirely from serialized histograms in report-data.json.

Deployment

JMeter Plugin

  • Copy shaded JAR → lib/ext/
  • Restart JMeter
  • Tools → TurviForge menu
  • Or: Add → Listener → Live Collector

CI/CD (Headless)

  • No JMeter installation needed
  • Single runnable JAR
  • SLA exit codes gate pipelines
  • JUnit XML for Jenkins/GitLab/GitHub
# JMeter non-GUI with auto-report jmeter -n -t test.jmx -l results.jtl \ -Jturviforge.autogenerate=true \ -Jturviforge.sla=sla.yaml

Technical Highlights

  • Log-linear histogram — 128 sub-buckets/band, 25 bands, deflate+base64 wire format
  • Adaptive CSV parser — reads any jmeter.save.saveservice.* column config at runtime
  • K-way merge — min-heap timestamp-ordered merge for distributed runs
  • LTTB downsampling — 2000-point visual cap, full data preserved in JSON
  • Live Collector — lock-free queue + 1s flusher, ≤2µs per sample on sampler threads
  • Deterministic output — same JTL + config → byte-identical report-data.json
  • Zero dependencies — hand-rolled JSON, YAML subset parser, no Jackson/SnakeYAML
