Advanced Reporting Plugin for Apache JMeter

v0.5.0 · Chandran Annapaneni · 2026

The Problem

JMeter's built-in dashboard: inaccurate, slow, no verdicts

❌ 10–30% percentile error

Coarse buckets miss p99/p99.9 where SLAs live

❌ No pass/fail

Descriptive only — no CI exit codes

❌ No comparison

Can't diff runs without external tools

❌ Fails at scale

Multi-hour soak tests crash the renderer

1–3 hours wasted per test cycle on manual analysis

The Solution

  • Exact percentiles — log-linear histogram, ≤0.78% error
  • SLA gates — YAML rules → PASS/DEGRADED/FAIL → exit codes
  • Run comparison — Mann-Whitney U + Cliff's delta
  • One HTML file — self-contained, offline, email-able
  • Constant memory — 10 GB+ JTL in <512 MB heap
  • Zero friction — one JAR, no test plan changes

CLI — One Command

java -jar turviforge-cli.jar generate \ --jtl results.jtl \ --out report/ \ --sla sla.yaml \ --junit \ --title "Checkout API — RC 2.4" → exit 0 (PASS) · report.html + junit.xml

Also: compare · validate · sla init (auto-generate SLA from data)

SLA Engine

rules: - match: "Checkout*" assert: - { metric: p95, op: "<", value: 800, warn: 700 } - { metric: error_rate, op: "<", value: 0.5 } - match: "TOTAL" assert: - { metric: throughput, op: ">=", value: 100 }

PASS → deploy  ·  DEGRADED → review  ·  FAIL → block pipeline

Comparison Engine

Statistically rigorous — no raw samples needed

  • Mann-Whitney U — significance from histogram ranks
  • Cliff's delta — effect size (|d| ≥ 0.147)
  • Regression flags — p95 ↑10%, errors ↑0.2pp, throughput ↓10%
  • Per-label table — delta breakdown in HTML report

Live Collector (Phase 4)

Real-time metrics during test execution

  • Lock-free queue — ConcurrentLinkedQueue, ≤2µs/sample
  • Background flusher — 1s drain into MetricsPipeline
  • Auto-report — generates HTML on test end
  • JMeter Listener — drag-and-drop in test plan
